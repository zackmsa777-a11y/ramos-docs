A practical native language · Simple syntax · Measured speed

Welcome to the Ramos Book

Ramos is a small, self-hosted language that compiles directly to native Linux x64 and Windows x64 executables. Its two guiding rules are simple programming and measured speed.

This book describes Ramos 0.25.1 preview. Markdown chapters are the canonical edition for AI agents, review and offline reading. The HTML edition is generated from those same chapters for comfortable human reading. Historical version labels identify when a feature arrived; they do not change this book's baseline.

What you can use today

Checked int64 and finite float64 arithmetic, booleans, functions, comments, while/range loops, else-if chains, compound assignment, immutable UTF-8 strings, mutable bytes, structs, typed arrays, reclaiming managed memory, compile-time weave, stdin, streamed files, terminal interfaces and Windows/Linux native GUI controls, directory iteration/creation, lexical path helpers, environment lookup, direct child execution and reusable UTF-8 text builders. Text builders provide immutable snapshots and capacity reuse/release for streamed tools.

Native math adds explicit conversions, square root and fixed decimal formatting. Decimal input adds fallible parsing for numerical CLI apps such as streamed statistics. There are no namespaces, networking APIs or package registry in 0.25.1. Read the OS libraries for directory and child-process contracts. See the new syntax for ranges, else-if chains and compound assignment. See the limits and proposed roadmap. Planned syntax must not be used in programs targeting this version.

Use ramos run app.ramos to compile and execute a source file directly, or build to save an executable. ramos fmt formats a copy or checks formatting. For desktop apps, use ramos run app.ramos --gui; Linux CLI/compiler output remains static. Authoring tools explain arguments, errors and cleanup.

Monotonic timing supports elapsed-time animation and native frame deadlines. The rmatrix project shows changed-cell terminal rendering.

Collection controls add explicit reserve/release, full-capacity status handling and signed integer sorting. rsort sorts stdin or a streamed file.

The application repositories pin their compiler and standard-library snapshot. The calculator's scientific functions are application library code in Ramos; they do not add new compiler intrinsics to this book's released baseline. Existing compiler test/release examples and the book's bundled examples remain available while new standalone example development takes place in ramos-examples.

The limits and negative results matter as much as working features. Native output is not proof of speed, and compiling for an OS is not proof that its interactive applications have been tested there.

Checked recursion supports 1,024 active calls within a separate 4 MiB stack budget. The scientific calculator uses it for 64 expression levels. Read compatibility and installation before updating a project.

Canvas drawing supplies bounded reusable commands for native lines, shapes and pixels. Repaint snapshots survive buffer reuse and garbage collection. The interactive plot runs on both desktops; opt-in logical DPI units are available in the scaling preview.

Exact numerical output provides scientific and compact strings. Seventeen significant digits preserve finite binary64 values, including signed zero; the calculator uses it for readable tiny and large results.

The 0.25 preview verifies initial native Windows DPI behavior and bounded resource churn, plus genuine GTK scale changes. The reported native Windows 144 → 168 → 96 sequence passed events/input/shutdown, but captures showed broken canvas shapes. The 0.25.1 repaint candidate needs a real-display visual retest; 200% was unavailable on the reported display. See the test commands. The practical 1.0 goal remains unfinished.
