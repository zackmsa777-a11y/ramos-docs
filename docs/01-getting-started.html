Install, build and run

Use the complete 0.22.0 recursion bundle, which also includes the CLI/TUI tools, both compilers, examples and all thirteen libraries. Extract the archive and keep its directory structure. The published SHA256SUMS file lists asset hashes for integrity checking.

Your first source file

Save hello.ramos as UTF-8 in the extracted directory:

fn main() {
    print(s"Hello, Ramos!")
}

Windows x64 — PowerShell

.\ramos.exe --version
.\ramos.exe run .\hello.ramos
.\ramos.exe build .\hello.ramos -o .\hello.exe
.\hello.exe

Expected output: Hello, Ramos!. Python, a C compiler and a separate runtime are not required for Windows/CLI programs with the downloaded compiler. Linux --gui programs additionally require system GTK3 and a desktop display; see GUI setup.

Linux x64 — shell

chmod +x ramos-linux-x86_64
./ramos-linux-x86_64 --version
./ramos-linux-x86_64 run hello.ramos
./ramos-linux-x86_64 build hello.ramos -o hello
./hello

Formatting and readable errors

./ramos-linux-x86_64 fmt hello.ramos --check
./ramos-linux-x86_64 fmt hello.ramos -o formatted-hello.ramos

Use .\ramos.exe for these commands in PowerShell. Source-line/caret errors help locate mistakes; authoring tools describe formatting, argument forwarding and temporary executable cleanup.

Rebuilding an existing output

Use --force only when you intend to replace an existing executable:

./ramos-linux-x86_64 build hello.ramos -o hello --force

A failed compilation preserves existing output. The compiler refuses source file aliases as output even with --force.

Libraries and example folders

For a root-level source file, use weave "stdlib/numbers.ramos". Sources inside examples/ use weave "../stdlib/numbers.ramos". Paths resolve relative to the source that contains the directive, not the terminal's working directory.

This documentation repository includes the same example and library sources. To use them, place the downloaded native compiler at the repository root:

./ramos-linux-x86_64 build examples/library_demo.ramos -o library-demo
./library-demo

.\ramos.exe build .\examples\library_demo.ramos -o .\library-demo.exe
.\library-demo.exe

Build from the compiler repository

In a checkout of the main Ramos repository, initial bootstrapping on Linux requires Make and GNU binutils. Python is used for validation, not as a runtime for generated programs.

make
./ramos build examples/hello.ramos -o hello --force
./hello
make install PREFIX="$HOME/.local"

Once built, the compiler emits executables without those bootstrap tools. Add the installation prefix's bin directory to PATH if needed. See self-hosting for verification commands.
